# 调度器管理的运行时进程出生与条件删除

本能力只在显式设置创建参数 --scheduler-resource-generation 时启用，并要求其值与可信 OCI 注解 akernel.scheduler/resource-generation 完全一致。第一版只支持独立根容器；没有这个参数的旧创建保留原接口。新的删除参数 --expected-resource-generation 要求完整容器 ID，并在原生状态锁内重新读取当前归属，不能使用 FetchSpec 缓存去删除已经替换的代际。状态不存在不会成为有代际删除的成功。

初始化器在实际创建 gofer 的位置记录直接子进程，在 Sentry 完成启动确认后记录仍未回收的直接子进程。出生记录包含容器、资源代际、进程角色、启动时间、程序 SHA256、参数 SHA256、cgroup SHA256、启动环境和 PID namespace；原参数与程序内容不写入记录。记录前后检查直接父进程、进程身份和 pidfd；不能在启动器退出后凭后来找到的 PID 补写出生。procfs 的 PID 编号必须与观察者的 PID namespace 对应。

受管理容器先持久保存创建意图，在实际运行时派发前保存 runtimeDispatched，随后保存子进程事实。受管理状态使用原目录句柄、独占临时文件、文件同步、原子重命名和目录同步。每份状态不超过 8 MiB。删除前在持有原生状态锁时核对原归属、原 spec、两个进程的出生和派发事实，拒绝重复字段、尾随内容、符号链接、FIFO、硬链接、权限不安全或变更的状态。缺失事实与已确认未派发分开处理。

新增 processLaunchVersion=1 分别保存 goferLaunchState 和 sentryLaunchState。初始值 not_dispatched 在任何对应派发前持久保存；dispatching 在启动对应进程之前持久保存；birth_published 与生产端捕获的原出生在同一份原子状态中发布。Sentry 派发意图必须在调用 sandbox.New 之前发布，不能在调用失败后补写未派发。旧没有这份阶段协议的记录保留原完整出生要求，带新阶段却丢失版本的混合记录拒绝。

只有阶段明确为 Sentry 未派发、原 gofer 出生已发布且事实完整一致时，清理才可以只取得原 gofer 句柄并确认其退出。这个阶段分类本身不授权信号；仍须核验原状态锁内的当前版本及真实出生，打开原 pidfd 后执行。任一 dispatching 阶段缺少已发布出生继续是结果未知，即使另一个进程的出生已经保存也不能改成“从未启动”。阶段缺失、矛盾、替换或未知版本全部拒绝。结构单元测试不执行信号；原 gofer 实际条件退出、消费者对部分状态的接线、完整安装包及节点预算仍待独立验收。

终止前先取得所有必需原进程的 pidfd；发现另一个角色已经被替换时，不先终止其邻居。之后向已持有的句柄发送 SIGKILL，通过该句柄的退出事件确认，不通过后来查到的数字 PID 发送信号或等待。PID 被重用、程序或归属变化、启动环境变化、句柄不支持和退出未知均返回错误。调用具有独立的二十秒上限，并继承有代际删除的上下文。停止失败时保留原生状态；受管理删除把状态和锁文件的移除放在宿主文件清理之后。

调度器继续拥有原 cgroup 的代际清理责任。受管理运行时不在停止后凭路径执行旧 cgroup 卸载，这些资源由 sandboxd 的原物理归属和资源步骤结算。运行时进程退出不等于整个沙箱退役，也不等于节点预算已经归还。

原进程缺失只有在完整原出生与相同观察范围下才能判定；runtimeDispatched 已设置但缺少原出生的部分启动保持未知。第一条子进程事实保存失败、启动器崩溃、其他初始化副作用、特殊检查点辅助进程及跨宿主恢复仍需要独立对账和验收。此源码和受控单元测试不证明实际生产程序、平台部署、全部运行时兼容或物理预算已经通过。

发布仍按项目既有候选流程构建完整 gvisor.tar.bz2，保持 runsc、containerd shim 及全部 gvisor-bin 辅助程序配套；经过 sandboxd 运行时套件和 AKernel standalone 验收后才推广同一组字节。不能仅替换 runsc 或提前修改消费者的安装包校验值。
